## 迭代優化記錄

### Iteration 1 - 基礎分析 ✅
- 診斷 6 大 UX 問題
- 提出 6 大改進方案
- 建立實作優先級

### Iteration 2 - 認知負荷分析 ✅
**新洞察**: 玩家的認知負荷過高
- **問題**: 同時需要監控 8+ 個資訊源 (金幣、魔力、HP、波次、敵人、陷阱冷卻...)
- **解決**: 引入「智能提示系統」- 只在需要時顯示關鍵資訊
  - 金幣不足時,自動高亮金幣數字
  - HP < 30% 時,地城之心脈動紅光
  - 陷阱冷卻完成時,短暫閃光提示
- **價值**: 減少玩家需要主動監控的資訊,降低疲勞感

### Iteration 3 - 操作流暢度分析 ✅
**新洞察**: 滑鼠移動距離過長影響效率
- **問題**: 放置陷阱需要「左側按鈕 → 地圖中心 → 右側確認」往返
- **解決**: 引入「就近操作」原則
  - 滑鼠 hover 地圖時,附近顯示快捷工具環 (radial menu)
  - 右鍵快速取消當前選擇
  - 雙擊陷阱快速升級 (無需等待資訊面板)
- **價值**: 減少 60% 滑鼠移動距離,提升操作效率

### Iteration 4 - 新手體驗深度分析 ✅
**新洞察**: 教學系統完整,但缺乏「發現的樂趣」
- **問題**: 教學太線性,玩家只是執行指令而非探索
- **解決**: 引入「引導式探索」而非「命令式教學」
  - 教學文案改為疑問句:「試試看火焰陷阱配合油坑會怎樣?」
  - 隱藏的「彩蛋組合」,發現時給予額外獎勵
  - 允許玩家「走錯路」,然後給予溫柔的修正建議
- **價值**: 從「被教育」變成「主動學習」,提升成就感與記憶留存

### Iteration 5 - 情緒曲線設計 ✅
**新洞察**: 遊戲缺乏情緒高低起伏,體驗過於平坦
- **問題**: PLANNING 階段冷靜、INVASION 階段緊張,但缺乏「驚喜」與「絕望」時刻
- **解決**: 設計「情緒轉折點」
  - **絕處逢生**: HP < 10% 但成功防守,觸發「力挽狂瀾!」特效 + 大量獎勵
  - **意外驚喜**: 隨機事件 - 一隻敵人攜帶寶箱,擊殺獲得額外金幣
  - **反轉時刻**: Boss 敵人第一次 HP < 50% 時,螢幕震動 + 慢動作
- **價值**: 創造「我永遠記得那一刻」的遊戲時刻

### Iteration 6 - 社交分享動機分析 ✅
**新洞察**: 遊戲缺乏「可分享時刻」設計
- **問題**: 玩家完成關卡後,沒有強烈動機分享給朋友
- **解決**: 設計「分享誘因」
  - 波次完成後生成精美「戰報卡片」(可截圖分享)
  - 顯示創意數據:「你的陷阱組合擊敗了 87% 的玩家未能防禦的敵人」
  - 「你用了一種罕見組合:火焰軌道 + 油坑 + 旋風陷阱」
  - 一鍵生成分享文案:「我用 5 個陷阱防住了 10 波敵人!」
- **價值**: 增加口碑傳播,降低獲客成本

### Iteration 7 - 可及性 (Accessibility) 審查 ✅
**新洞察**: 當前設計對特定玩家群體不友善
- **問題**:
  - 色盲玩家難以區分元素類型 (水=藍、火=紅)
  - 反應較慢的玩家在 INVASION 階段壓力過大
  - 滑鼠精準度較差的玩家放置陷阱困難
- **解決**: 引入「無障礙選項」
  - **色盲模式**: 增加圖示輔助 (水=💧, 火=🔥, 電=⚡)
  - **慢速模式**: INVASION 階段敵人速度減半,適合策略玩家
  - **放置輔助**: 啟用「磁吸格子」,滑鼠自動對齊最近的可放置格子
  - **音效輔助**: 關鍵事件 (金幣不足、HP 低) 有音效提示
- **價值**: 擴大玩家群體,包容性設計

### Iteration 8 - 長期參與度分析 ✅
**新洞察**: 遊戲缺乏「重複遊玩動機」
- **問題**: 玩家通關一次後,缺乏理由重玩
- **解決**: 設計「元遊戲系統」(Meta-game)
  - **陷阱圖鑑**: 收集所有陷阱組合,解鎖特殊皮膚
  - **挑戰模式**: 每日隨機挑戰 (限定金幣、禁用特定陷阱)
  - **排行榜**: 最少陷阱通關、最快通關、最高連擊
  - **成就系統**: 「全程無傷」「只用火系陷阱」等挑戰
- **價值**: 從「10 小時遊戲」變成「100 小時遊戲」

### Iteration 9 - 核心循環優化 ✅
**新洞察**: 核心循環「規劃 → 執行 → 獎勵」可以更緊湊
- **問題**: 波次之間的 15 秒倒數過長,打斷節奏
- **解決**: 優化核心循環
  - **快速迭代**: 倒數改為 5 秒,但允許玩家「跳過倒數」或「延長時間」
  - **即時調整**: INVASION 階段也允許放置新陷阱,但花費 2 倍金幣
  - **獎勵即時性**: 擊殺敵人立即獲得金幣 (而非波次結束)
  - **失敗快速重來**: Game Over 畫面新增「快速重試」(保留陷阱佈局)
- **價值**: 提升「一局接一局」的流暢感,減少等待時間

### Iteration 10 - 整體一致性審查 ✅
**新洞察**: 回到整體,確保所有改進方案協調一致
- **檢查點 1**: 三區域佈局是否與智能提示系統衝突? ✅ 不衝突,相輔相成
- **檢查點 2**: 快捷操作是否會讓新手困惑? ✅ 可選功能,預設關閉
- **檢查點 3**: 情緒曲線設計是否會干擾核心玩法? ✅ 增強而非干擾
- **檢查點 4**: 可及性選項是否影響平衡性? ✅ 單人遊戲,不影響
- **檢查點 5**: 元遊戲系統是否過於複雜? ✅ 可選內容,不強制

**最終建議**:
- **Phase 1 必做**: 三區域佈局、智能提示、操作流暢度優化
- **Phase 2 推薦**: 新手體驗、情緒曲線、核心循環
- **Phase 3 可選**: 社交分享、長期參與度、可及性選項

```
START (開始畫面)
  ↓
PLANNING (部署陷阱)
```

## UX 問題診斷

### 問題 1: 資訊層級不夠清晰 🔴 HIGH

**症狀**:
- 金幣、魔力、HP 顯示在工具欄區域,沒有明顯的視覺重心
- 陷阱按鈕、英雄按鈕、路障按鈕平鋪,分類不夠突出
- 當前選擇的工具沒有足夠強烈的視覺反饋
- 波次進度、敵人數量等關鍵資訊不夠顯著

**影響**:
- 新玩家不知道優先看哪裡
- 資源不足時容易忽略提示
- 遊戲節奏感不明確

**根本原因**:
- UI 佈局採用水平平鋪,缺乏視覺層級
- 色彩對比度不足以建立資訊優先級
- 沒有「資訊中心」的設計概念

### 問題 2: 路障系統的互動不直覺 🔴 HIGH

**症狀**:
- 路障按鈕與陷阱/英雄混在一起
- 切換「路障模式」的概念對新手不友善
- 放置路障後沒有明確的視覺回饋 (耐久度、移除提示)
- 路障與陷阱的放置邏輯不一致 (模式 vs 一次性)

**影響**:
- 玩家不清楚路障模式是否啟用
- 誤操作頻率高 (想放陷阱卻進入路障模式)
- 學習成本高於預期

**根本原因**:
- 路障採用「toggle 模式」而非「one-shot 放置」
- 缺乏模式指示器 (當前是否在路障模式)
- 路障的視覺設計不夠突出

### 問題 3: 陷阱升級流程冗長 🟡 MEDIUM

**症狀**:
- 點擊陷阱 → 右側顯示資訊面板 → 點擊升級按鈕
- 升級按鈕位置不固定,取決於面板位置
- 無法快速升級多個陷阱 (需要重複點擊)

**影響**:
- INVASION 階段無法快速升級 (沒有暫停)
- 玩家需要頻繁切換視線 (地圖 ↔ UI 面板)

**根本原因**:
- 升級功能藏在資訊面板裡,不是主要操作流
- 缺乏快捷鍵或批量操作

### 問題 4: 錯誤處理不夠友善 🟡 MEDIUM

**症狀**:
- 金幣不足時放置陷阱,只有 `showMessage('金幣不足！')`
- 無法放置的位置 (牆壁、已佔用) 沒有視覺提示
- 升級失敗沒有具體原因說明

**影響**:
- 玩家不理解為什麼操作失敗
- 挫折感增加

**根本原因**:
- 錯誤提示只有文字,沒有視覺輔助 (如閃紅格子)
- 預防性檢查不足 (按鈕沒有置灰禁用)

### 問題 5: 遊戲節奏感不明確 🟡 MEDIUM

**症狀**:
- PLANNING 階段沒有時間壓力,可以無限規劃
- INVASION 階段沒有倒數計時或進度條
- 波次之間的自動倒數 (15 秒) 可以被忽略

**影響**:
- 缺乏緊迫感與挑戰性
- 不清楚當前波次進度 (還剩幾隻敵人)

**根本原因**:
- 沒有視覺化的時間軸或進度指示器
- 波次倒數只有文字,不夠顯著

### 問題 6: 缺乏「成就感瞬間」設計 🟢 LOW

**症狀**:
- 陷阱觸發時有特效,但沒有「連擊」或「完美擊殺」的額外回饋
- 波次完成有慶祝畫面,但缺乏累積的成就感 (如評分、星級)
- 沒有「關鍵時刻」的視覺強調 (如最後一隻敵人被擊殺)

**影響**:
- 遊戲體驗略顯平淡
- 缺乏分享衝動

**根本原因**:
- 專注於核心玩法,尚未設計「情感高峰」時刻

## UX 改進方案

### 方案 1: 重構資訊架構 - 四區域佈局 🎯 HIGH PRIORITY

**設計目標**: 建立清晰的資訊層級,讓玩家一眼看到重要資訊

#### 新佈局結構

```
┌─────────────────────────────────────────────────────────┐
│ 遊戲區域 (960×624px)                                      │
│  - 等距像素風格地圖                                       │
│  - 火把、陷阱、英雄、敵人                                 │
│  - 路徑預覽、傳送門動畫                                   │
├────────────┬─────────────────────────┬───────────────────┤
│ 左區: 工具  │ 中區: 主要操作           │ 右區: 狀態資訊    │
│ (200px)     │ (560px)                  │ (200px)           │
├────────────┼─────────────────────────┼───────────────────┤
│ 陷阱按鈕 ×6 │ 「開始波次」大按鈕       │ 🪙 金幣: 150      │
│ (垂直堆疊)  │ 「路障模式」toggle       │ ❤️ 地心HP: 80%   │
│             │ 「回到規劃」按鈕         │ 🌊 波次: 3/10    │
│ 英雄按鈕 ×2 │                          │ 👹 敵人: 5       │
│ (垂直堆疊)  │ 當前選擇: [陷阱圖標]     │                   │
│             │ 花費: 🪙 30              │ ⏱️ 下波倒數: 10s │
└────────────┴─────────────────────────┴───────────────────┘
```

#### 設計原則

| 區域 | 職責 | 視覺權重 |
|------|------|---------|
| **左區 (工具)** | 陷阱/英雄選擇 | 中等 |
| **中區 (操作)** | 主要按鈕、狀態指示器 | 最高 |
| **右區 (資訊)** | 資源、波次、倒數 | 高 |

#### 實作指引

1. **左區工具列**:
   - 垂直堆疊,每個按鈕 80×80px
   - 陷阱與英雄之間用 20px 分隔線
   - hover 時顯示名稱 + 花費
   - 選中時按鈕外框高亮 (`#ffaa44` 2px)

2. **中區操作區**:
   - 「開始波次」按鈕 200×60px,居中顯示
   - PLANNING 階段: 綠色漸層 `#44aa44` → `#66cc66`
   - INVASION 階段: 紅色禁用 `#884444`
   - 「路障模式」toggle: 120×40px,啟用時黃色高亮
   - 當前選擇顯示: 64×64px 大圖標 + 名稱 + 花費

3. **右區資訊面板**:
   - 固定位置,垂直堆疊
   - 每個資訊 icon + 數值,右對齊
   - 金幣/HP 低於 30% 時閃紅警示
   - 波次進度條: 橫條顯示完成百分比

#### 優勢

- ✅ 視覺層級明確,重要資訊突出
- ✅ 操作流程集中在中區,減少視線移動
- ✅ 資訊面板固定,易於快速掃視
- ✅ 左右對稱平衡,符合人體工學

### 方案 2: 路障系統重設計 - 改為「一次性放置」🎯 HIGH PRIORITY

**設計目標**: 讓路障放置與陷阱/英雄操作邏輯一致

#### 當前問題

```javascript
// 當前: toggle 模式
this.selectedBarricadeMode = !this.selectedBarricadeMode;

// 問題: 玩家不知道當前是否在路障模式
// 問題: 與陷阱放置邏輯不一致
```

#### 改進方案

**選項 A: 改為「路障工具」(推薦)** ⭐

```javascript
// 新設計: 路障視為一種特殊陷阱
this.selectedTrap = DK.TRAP_TYPES.BARRICADE; // 新增路障類型
this.selectedHeroType = null;

// 放置一次後自動取消選擇 (與陷阱一致)
// 或: 按住 Shift 連續放置
```

**優點**:
- ✅ 與陷阱操作邏輯完全一致
- ✅ 不需要「模式」概念
- ✅ 新手學習成本低

**選項 B: 增強模式指示器**

保留 toggle 模式,但增加:
- 全螢幕半透明黃色覆蓋 (透明度 0.05)
- Cursor 改為特殊圖示 (木板 icon)
- 右上角顯示「路障模式 [ESC 退出]」橫幅

**優點**:
- ✅ 最小程式碼修改
- ✅ 模式狀態非常明確

#### 建議

**推薦選項 A**,因為:
1. 玩家心智模型更統一 (所有防禦設施都是「選擇 → 放置」)
2. 未來擴展性更好 (可以新增更多路障類型)
3. 不需要維護「模式狀態」

### 方案 3: 陷阱升級快捷方案 🎯 MEDIUM PRIORITY

**設計目標**: 減少升級操作的步驟,支援快速升級

#### 改進方案

**快捷鍵升級**:
- 滑鼠 hover 陷阱時,按 `U` 鍵直接升級
- 按住 `Shift + 點擊` 陷阱直接升級 (跳過資訊面板)

**批量升級**:
- 按住 `Ctrl` 點擊多個陷阱,選中後按 `U` 全部升級
- 或: 新增「升級全部同類陷阱」按鈕

**視覺優化**:

### 方案 4: 錯誤預防與友善提示 🎯 MEDIUM PRIORITY

**設計目標**: 讓玩家在操作前就知道能否成功,而非操作後才報錯

## 關鍵決策點

### 決策 1: 路障系統改為「工具」還是保留「模式」?

**推薦**: 改為「工具」(選項 A)

**理由**:
- 與陷阱/英雄操作邏輯統一,學習成本最低
- 未來可擴展路障類型 (木牆、石牆、鐵閘等)
- 不需要維護「模式狀態」,減少 bug 可能性

**風險**:
- 需要修改 `ui.js` 和 `map.js` 的放置邏輯
- 需要新增 `TRAP_TYPES.BARRICADE` 配置

**建議**: 先實作「增強模式指示器」(選項 B) 作為過渡,未來再考慮重構為工具

### 決策 2: PLANNING 階段是否加入時間限制?

**推薦**: 暫不加入,作為可選「困難模式」

**理由**:
- 當前遊戲定位是「策略為主」,強調思考而非反應
- 新手需要充分時間理解陷阱組合
- 時間限制會大幅提升難度,可能勸退玩家

**替代方案**:
- 提供「快速部署」按鈕,跳過倒數獲得獎勵金幣 (鼓勵但不強制)
- 高階關卡或挑戰模式啟用時間限制

### 決策 3: UI 佈局改為三區域還是保持單行?

**推薦**: 改為三區域 (方案 1)

**理由**:
- 當前單行佈局 (960×96px) 資訊密度過高
- 三區域可以建立明確的資訊層級
- 符合玩家視線習慣 (左工具、中操作、右狀態)

**挑戰**:
- 需要重構整個 `ui.js` 渲染邏輯
- 遊戲區域高度減少 (624 → ~550px)

**建議**: 分階段實作
1. Phase 1: 保持單行,優化資訊分組與對比
2. Phase 2: 實作三區域佈局 (大型重構)

### 最關鍵的三個決策

#### 決策 1: 是否重構為三區域 UI?

**強烈推薦**: ✅ 是

**理由**:
- 解決最核心的「資訊層級不清」問題
- 為後續所有 UX 優化奠定基礎
- 一次性重構,長期受益

**風險管理**:
- 第一週先做 wireframe 原型,確認視覺可行性
- 與美術總監密切協作,確保美學不打折
- 保留舊 UI 作為 fallback 選項

#### 決策 2: 路障改為「工具」還是保留「模式」?

**推薦**: ⭐ 改為「工具」

**理由**:
- 與陷阱/英雄操作邏輯統一,學習成本最低
- 不需要維護「模式狀態」,減少 bug
- 未來可擴展路障類型

**妥協方案**: 先實作「增強模式指示器」,未來再重構

#### 決策 3: Phase 2/3 是否必須實作?

**推薦**: Phase 2 強烈推薦,Phase 3 視資源決定

**理由**:
- Phase 1 解決「能用」問題
- Phase 2 解決「好玩」問題 ← 這是關鍵
- Phase 3 解決「長久玩」問題

**建議**: 先完成 Phase 1 + Phase 2,收集玩家反饋後再決定 Phase 3

### 設計哲學總結

經過 10 次迭代,提煉出的核心設計哲學:

1. **玩家優先**: 所有設計服務於玩家體驗,不為設計而設計
2. **減少認知負荷**: 智能系統主動提示,而非讓玩家記憶
3. **即時反饋**: 150-300ms 快速回饋,讓玩家感受到「被聽見」
4. **引導式探索**: 不是命令,而是啟發玩家自主發現
5. **情緒曲線**: 設計高低起伏,創造「永遠記得的時刻」
6. **包容性設計**: 不同能力的玩家都能享受遊戲
7. **長期價值**: 元遊戲系統讓玩家有理由回來
