# ProjectDK 創意總監 — 設計標準與審查基準

> **創意總監審查基準文件**
> 用於統一視覺風格、確保設計一致性、提升玩家體驗

---

## 📋 文件目的

本文件作為所有設計方案的審查標準,確保：
1. **視覺風格統一**：Dungeon Keeper + Dungeon Warfare 3 風格融合
2. **設計語言一致**：色彩、字體、圖標、動畫保持協調
3. **用戶體驗流暢**：資訊層次清晰、互動直覺、視覺引導明確
4. **技術可行性**：Pure vanilla JS + Canvas 像素風格實作

---

## 🎨 核心視覺風格

### 整體美術風格
- **像素藝術**：16×16 tile, 3x 放大顯示（48px）
- **色彩基調**：黑暗地城（深紫灰牆、暖黃地板）+ 鮮明元素色
- **燈光氛圍**：火把照明、脈動光暈、環境反光
- **動畫風格**：微動畫（呼吸、脈動、閃爍）+ 快速反饋（150-300ms）

### 參考遊戲風格
1. **Dungeon Keeper (1997)**
   - 地下城主視角（防守方）
   - 黑暗幽閉空間美學
   - 火把照明、石牆紋理

2. **Dungeon Warfare 3 (2024)**
   - 像素風塔防
   - 陷阱觸發特效
   - 清晰的視覺回饋

- ✅ **元素識別度**：相似功能使用同色系（如所有陷阱冷卻條用元素色）
- ✅ **視覺層次**：前景（UI/文字）> 中景（單位/陷阱）> 背景（地磚）

## 📐 佈局與空間設計

### 畫面結構
```
┌─────────────────────────────────────┐
│  遊戲區域（960×624px, 低解析 Canvas） │
│  - 320×208 像素畫布 3x 放大          │
│  - 20×13 格 viewport (40×26 世界)    │
│  - 火把光暈、環境動畫                │
├─────────────────────────────────────┤
│  UI 區域（960×96px, 高解析 Canvas）   │
│  - 工具欄按鈕（陷阱/英雄/路障）       │
│  - 狀態列（金幣/地心HP/波次）         │
│  - 快捷鍵提示                        │
└─────────────────────────────────────┘
```

### 工具欄設計（已實作）
- **按鈕尺寸**：動態計算（約 120px × 70px）
- **分類分隔**：14px 間隔區分陷阱/英雄/路障
- **視覺回饋**：hover 高亮、選中邊框、數量徽章

### 審查要點
- ✅ **資訊密度**：避免過擠，重要資訊留白充足
- ✅ **視覺引導**：新手應能一眼看到「開始波次」按鈕
- ✅ **響應式考量**：小螢幕時按鈕文字不重疊

## 🎬 動畫與特效標準

### 微動畫原則
- **脈動光暈**：2000ms 週期，0.8-1.0 alpha
- **呼吸動畫**：sine 曲線，±0.5px 浮動
- **閃爍提示**：150ms 快閃，視覺回饋明確

### 特效層次
1. **環境特效**（背景層）：火把、水波、草叢擺動
2. **戰鬥特效**（中景層）：陷阱觸發、魔法連線、敵人受擊
3. **UI 特效**（前景層）：金幣粒子、傷害數字、波次完成慶祝

### 審查要點
- ✅ **效能考量**：粒子數量 < 50/幀，避免卡頓
- ✅ **可讀性**：特效不遮擋關鍵資訊（HP條、陷阱冷卻）
- ✅ **一致性**：同類事件用同種特效（如所有「觸發」都用 150ms 白閃）

## 🎯 用戶體驗設計原則

### 資訊層次
1. **最高優先**：地城之心 HP、當前金幣、波次進度
2. **次要資訊**：陷阱冷卻時間、英雄 HP、敵人數量
3. **輔助資訊**：Tooltip、快捷鍵提示、教學箭頭

### 視覺回饋
- **即時反饋**：點擊陷阱 → 立即顯示冷卻條
- **狀態指示**：英雄光環範圍、路障剩餘血量、草叢燃燒狀態
- **錯誤提示**：金幣不足時按鈕變灰 + Tooltip 提示

### 審查要點
- ✅ **3 秒原則**：新玩家 3 秒內理解核心操作
- ✅ **無文字可理解**：圖標/色彩足夠表達功能（色盲友善）
- ✅ **錯誤容忍**：誤操作可撤銷（如英雄回收全額退款）

## 🔧 技術實作約束

### Canvas 雙層架構
- **低解析層（game-canvas）**：像素藝術、環境、單位
- **高解析層（ui-canvas）**：文字、UI 按鈕、Tooltip

### 效能目標
- **60 FPS**：主循環 < 16.67ms
- **地磚快取**：所有靜態地磚預渲染
- **視錐剔除**：僅渲染 viewport 內物件

### 審查要點
- ✅ **Pure JS**：不引入框架，保持輕量
- ✅ **模組化**：新功能放獨立檔案（如 portal.js）
- ✅ **向下相容**：新設計不破壞已實作系統

## 🎯 五位設計師的審查重點

### 1. visual-designer（傳送門與地城之心）
- **重點**：傳送門視覺與地城之心的風格協調
- **挑戰**：傳送門需要明顯區別，但不能過於花俏
- **期待**：脈動光環、傳送特效、地心受傷視覺

### 2. toolbar-designer（工具欄分類）
- **重點**：陷阱/英雄/路障的分類視覺層次
- **挑戰**：按鈕數量多，如何避免擁擠
- **期待**：清晰的分隔線、統一的圖標風格、數量徽章設計

### 3. room-designer（房間系統）
- **重點**：房間地磚與走廊地磚的視覺差異
- **挑戰**：不破壞現有地圖美學
- **期待**：房間邊界指示、功能光環、訓練室/寶庫差異化

### 4. trap-designer（陷阱系統）
- **重點**：進化陷阱的視覺升級感
- **挑戰**：冷卻條/啟動閃光已實作，如何進一步優化
- **期待**：雷暴電擊板特效、油焰陷阱九宮格視覺、極寒風壓冰霜

### 5. minimap-designer（小地圖導航）
- **重點**：小地圖符號系統的清晰度
- **挑戰**：40×26 地圖縮小後仍可辨識
- **期待**：敵人動態標記、地心/陷阱/英雄符號、點擊跳轉

## 📌 審查流程

1. **接收設計文檔**：設計師提交 docs/*.md
2. **初步審查**：檢查設計清單 ✓/✗
3. **提出建議**：具體的改進方向（色彩/佈局/動畫）
4. **協調衝突**：解決不同系統間的視覺矛盾
5. **批准實作**：通過審查後允許進入實作階段
