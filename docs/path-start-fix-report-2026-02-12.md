- 視覺中心在 `(col*16 + 16, row*16 + 16)`

```javascript
{ x: hole.col * T + T, y: hole.row * T + T }  // T = 16 (TILE_SIZE)
```

**驗證計算**（假設 hole = {col: 8, row: 1}）：
- `x = 8 * 16 + 16 = 144` ✓
- `y = 1 * 16 + 16 = 32` ✓

## 🎯 根本原因

**瀏覽器快取問題**

用戶看到錯誤的路徑起點是因為：
1. **瀏覽器載入了舊版本的 JavaScript**
2. 修改的代碼沒有被重新載入
3. 開發者工具可能顯示舊的代碼

**證據**：
- 代碼邏輯正確 ✓
- 測試環境渲染正常 ✓
- 用戶環境看不到新代碼 ✗

## ✅ 解決方案

### 方案 1：硬重新載入（推薦）

**步驟**：
1. **Mac**: 按 `Cmd + Shift + R`
2. **Windows**: 按 `Ctrl + Shift + R`
3. 或右鍵重新載入按鈕 → 選擇「清除快取並硬性重新載入」

### 方案 2：清除瀏覽器快取

**Chrome / Edge**：
1. 開啟 DevTools (`F12`)
2. 右鍵點擊重新載入按鈕
3. 選擇「清除快取並硬性重新載入」

**或**：
1. 設定 → 隱私權與安全性 → 清除瀏覽資料
2. 選擇「快取的圖片和檔案」
3. 清除資料

### 方案 3：停用開發期間的快取

**DevTools 設定**：
1. 開啟 DevTools (`F12`)
2. Network 標籤
3. 勾選「Disable cache」
4. 保持 DevTools 開啟

### 方案 4：重啟本地伺服器

**如果使用本地開發伺服器**：
```bash
# 停止伺服器
killall -9 python3  # 或 killall -9 node

# 重新啟動
cd /path/to/projectdk
python3 -m http.server 8000
```

## 🔧 技術細節

### 傳送門中心計算公式

```javascript
// 傳送門左上角格子座標
const hole = { col: 8, row: 1 };

// 視覺中心像素座標（2×2 格子的中心）
const centerX = hole.col * TILE_SIZE + TILE_SIZE;  // 8*16 + 16 = 144
const centerY = hole.row * TILE_SIZE + TILE_SIZE;  // 1*16 + 16 = 32
```

**為什麼是 `col * T + T` 而不是 `col * T + T/2`？**

因為傳送門是 **2×2 格子**：
- 左上角格子中心：`(col * T + T/2, row * T + T/2)`
- 2×2 區域中心：`(col * T + T, row * T + T)`

**示意圖**：
```
格子 (8,1):        格子 (9,1):
┌────────┐        ┌────────┐
│  ·     │        │     ·  │
│        │        │        │
└────────┘        └────────┘
格子 (8,2):        格子 (9,2):
┌────────┐        ┌────────┐
│        │        │        │
│     ●  │◄──── 2×2 中心 (144, 32)
└────────┘        └────────┘
```

### 路徑點陣列構建

```javascript
const points = [
```

## 🎓 經驗教訓

### 1. 語法正確 ≠ 用戶看到正確的代碼

**問題**：
- 代碼邏輯完全正確
- 測試環境運行正常
- 但用戶仍看不到效果

**原因**：
- 瀏覽器快取載入舊版本 JavaScript
- 開發者工具可能顯示快取的代碼

**解決**：
- **永遠先嘗試硬重新載入** (`Cmd+Shift+R`)
- 開發時啟用「Disable cache」
- 驗證時使用無痕模式

### 2. 視覺問題需要視覺驗證

**問題**：
- 計算邏輯正確不代表渲染正確
- Console 沒有錯誤不代表視覺正確

**解決**：
- 創建獨立的視覺測試頁面
- 使用簡化的測試環境
- 截圖對比預期與實際效果

### 3. 調試輸出要及時移除

**問題**：
- `console.log` 會影響性能（每幀都輸出）
- 大量日誌會淹沒重要信息

**解決**：
- 只在診斷時加入調試輸出
- 問題解決後立即移除
- 或使用條件編譯（開發環境才啟用）
