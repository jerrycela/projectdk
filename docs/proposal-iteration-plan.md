# ProjectDK 遊戲企劃書分析與 10 次迭代優化計劃

## 一、企劃書優缺點分析

### ✅ 優點

1. **核心機制描述清晰**
   - 元素反應系統解釋詳細，配有觸發條件、效果、視覺表現
   - 光環進化機制邏輯完整，戰術意義明確
   - 地牢之心系統設計有創新性（主動破牆）

2. **技術架構透明**
   - 完整的程式碼結構、技術棧說明
   - 效能優化策略具體（視埠剔除、距離場快取）
   - 開發進度可追蹤（✅/🔲 標記）

3. **視覺設計有獨特性**
   - 金髮魔王女神角色設計有記憶點
   - 像素藝術風格定位明確（16×16 精細度）
   - 暗黑地牢 + 優雅英雄的反差美學

4. **商業規劃結構完整**
   - 三階段發布策略（Web → Steam → 手機）
   - 各平台收益模式清楚（免費+贊助、付費、IAP）
   - 風險評估與應對措施具體

### ❌ 缺點

1. **市場數據嚴重不足**
   - 競品分析缺乏具體數據（銷量、收益、玩家數）
   - 收益預估缺乏依據（itch.io $500-$2,000 從何得出？）
   - 目標市場規模未量化（「中輕度策略玩家」有多少人？）

2. **玩家體驗設計薄弱**
   - 學習曲線設計只有一張表格，沒有具體教學流程
   - 單局遊戲節奏未詳述（15-30 分鐘內如何分配 10 波次？）
   - 玩家留存機制不明（如何讓玩家玩完第一關後繼續玩？）

3. **競品差異化論證不足**
   - 「我們有元素反應」但未證明為什麼玩家會因此選擇我們
   - Kingdom Rush、Bloons TD 6 都有成熟的升級系統，光環進化如何更好？
   - 缺乏「為什麼現在做這款遊戲」的市場時機分析

4. **營運計劃過於樂觀**
   - Steam 10,000 份銷量無依據（同類獨立塔防真實數據？）
   - 手機版 50,000 下載、ARPU $1.50 過於理想化
   - 缺乏失敗場景的應對（如果 itch.io 階段無人問津怎麼辦？）

5. **團隊與資源規劃模糊**
   - 「1-2 人核心開發」能在 4 個月完成 MVP 嗎？
   - 外包音效 $2,000 是市場行情嗎？
   - 測試社群如何建立？目前有多少種子用戶？

6. **財務模型缺失**
   - 沒有開發成本估算（人力、外包、伺服器、行銷）
   - 沒有現金流預測（何時達到收支平衡？）
   - 沒有投資回報率分析（投入 X 萬，何時回本？）

7. **技術風險評估過於輕描淡寫**
   - 「Web 效能問題（大量粒子）」影響只評為「中」，實際可能導致玩家流失
   - 跨瀏覽器相容性標為「低」，但 Safari 的 Canvas 效能問題可能嚴重
   - 手機移植複雜度「中」，實際可能需要重構整個操作系統

8. **缺乏可衡量的里程碑**
   - 「Month 1-2: 完成冰法師 + 光環進化 + 教學」太籠統
   - 沒有可驗證的成功指標（例如：「教學關卡完成率 >80%」）
   - 沒有 Beta 測試的具體目標（多少玩家？什麼反饋？）

## 二、10 次迭代優化方向

| 迭代 | 優化重點 | 具體改進內容 | 預期效果 |
|------|---------|-------------|---------|
| **#1** | **補充市場數據與競品深度分析** | • 加入塔防遊戲市場規模、增長率、玩家畫像<br>• 競品銷量/收益數據（Steam、手機榜單）<br>• 元素反應機制在其他遊戲的成功案例（原神、Hades）<br>• 目標市場人數估算（Steam 標籤數據、Discord 社群規模） | 增強投資者信心、證明市場需求真實存在 |
| **#2** | **強化差異化競爭優勢論證** | • 為什麼元素反應系統比傳統塔防升級樹更吸引玩家？<br>• 光環進化 vs Kingdom Rush 英雄技能，哪個策略深度更高？<br>• 主動破牆系統的創新性量化（市面上有多少塔防做到？）<br>• 用戶訪談/問卷結果（如果有） | 說服讀者「這款遊戲值得做」，不是重複造輪子 |
| **#3** | **設計完整的玩家旅程地圖** | • 新玩家前 5 分鐘體驗（首次開洞 → 部署第一個陷阱 → 第一次元素反應）<br>• 教學關卡 step-by-step 流程（3 波內教會所有核心機制）<br>• 關卡解鎖曲線（第 1-10 關的難度與系統開放節奏）<br>• 玩家留存機制（每日任務、成就系統、排行榜） | 確保新玩家能「玩下去」，降低流失率 |
| **#4** | **建立可信的財務模型** | • 開發成本估算（人力、外包、工具、行銷）<br>• 現金流預測（月度收入/支出，何時轉正）<br>• 敏感度分析（如果銷量只有預期 50%/150% 怎麼辦）<br>• 投資回報率分析（投入 X 萬，Y 個月回本）<br>• 引用行業基準（獨立遊戲平均開發成本、收益中位數） | 讓投資者/高層看到「這是可行的」，不是空想 |
| **#5** | **細化時間表與可驗證里程碑** | • 每個月的具體交付物（例如：「Month 1 結束前完成冰法師攻擊動畫、暴風雪粒子效果」）<br>• 可量化的成功指標（例如：「教學完成率 >80%」、「平均單局時長 20-25 分鐘」）<br>• Beta 測試計劃（何時招募、多少人、如何收集反饋）<br>• 里程碑檢查點（若 Month 2 未完成教學，延後 Steam 版） | 讓團隊有明確目標、讓投資者能追蹤進度 |
| **#6** | **補充用戶獲取與行銷策略** | • itch.io 如何獲取首批用戶？（社群、YouTube、Twitch）<br>• Steam 發布行銷預算（願望單、評測、折扣）<br>• 手機版 ASO 策略（關鍵字、截圖、試玩影片）<br>• 社群經營計劃（Discord、Reddit、Twitter）<br>• KOL/實況主合作計劃 | 確保「做出來」後有人知道、有人玩 |
| **#7** | **深化技術風險與應對方案** | • Web 效能瓶頸測試結果（最低配置電腦能跑嗎？）<br>• 手機移植技術驗證（Canvas → WebGL？原生？）<br>• 跨平台存檔同步方案（Steam Cloud、iCloud）<br>• 作弊/修改器風險（單機遊戲排行榜如何防作弊？）<br>• 技術債務管理（Pure JS 未來是否需要重構為 TypeScript？） | 避免技術問題拖累上線、確保多平台體驗一致 |
| **#8** | **補充團隊與外包管理計劃** | • 核心開發者技能樹（是否有 Canvas 優化經驗？）<br>• 像素藝術師作品集（過往案例、風格匹配度）<br>• 音效外包商選擇標準（價格、質量、版權）<br>• 任務管理工具（Trello、Jira、Notion？）<br>• 版本控制與 CI/CD 流程 | 確保團隊能高效協作、外包質量可控 |
| **#9** | **設計 Plan B 應急方案** | • 如果 itch.io 階段無人問津：縮減 Steam 版範圍？轉型免費 Web 遊戲？<br>• 如果 Steam 銷量不佳：降價？DLC 策略調整？轉向手機？<br>• 如果開發延期：哪些功能可砍（冰法師？無盡模式？）<br>• 如果資金不足：眾籌？天使投資？自費？<br>• 每個階段的「停損點」（何時該放棄這個項目） | 降低風險、讓決策者知道「我們有備案」 |
| **#10** | **加入成功案例與社會證明** | • 引用類似項目成功案例（Slay the Spire、Celeste 如何從小做大）<br>• 團隊過往成績（如果有）<br>• 早期測試者反饋引述<br>• 行業專家/投資人背書（如果有）<br>• 遊戲獎項/比賽入圍（如 IGF、IndieCade） | 建立信任感、證明「我們做得到」 |

## 三、優先級建議

### 🔴 高優先級（投資者最在意）
- **#1 市場數據** - 沒有數據就是空談
- **#4 財務模型** - 不知道錢怎麼流就不會投
- **#2 差異化論證** - 為什麼要投你而不是投別人

### 🟡 中優先級（執行層面）
- **#5 時間表細化** - 確保能按時交付
- **#3 玩家旅程** - 確保做出來的東西有人玩
- **#6 行銷策略** - 確保有人知道你的遊戲

### 🟢 低優先級（加分項）
- **#7 技術風險深化** - 技術人看得懂，但非必要
- **#8 團隊計劃** - 如果是個人項目可簡化
- **#9 Plan B** - 有更好,沒有也還行
- **#10 成功案例** - 錦上添花

---

## 四、建議執行順序

```
第 1 輪：#1 市場數據 + #4 財務模型（硬數據，給投資者看）
第 2 輪：#2 差異化論證 + #3 玩家旅程（證明遊戲好玩）
第 3 輪：#5 時間表 + #6 行銷策略（證明能做出來、有人玩）
第 4 輪：#7 技術風險 + #8 團隊計劃（執行細節）
第 5 輪：#9 Plan B + #10 成功案例（風險管理 + 信任背書）
```

## 五、給企劃書作者的誠實建議

### 👍 這份企劃書已經做得很好的地方

- 核心機制設計完整、有創意
- 技術架構清晰、可實現
- 視覺風格有辨識度
- 結構完整、易讀

### 🚨 但如果要拿去融資/提案，目前的問題是

1. **缺乏說服力的數據** - 投資者會問「憑什麼 Steam 能賣 10,000 份?」
2. **風險意識不足** - 所有預估都是樂觀情境，沒有 worst-case scenario
3. **執行細節模糊** - 「1-2 人核心開發」聽起來不靠譜
4. **市場定位不夠鋒利** - 「中輕度策略玩家」太廣泛，真正的目標用戶是誰？

### 💡 如果是內部開發文件

- 這份企劃書已經夠用
- 但建議補充 #3（玩家旅程）和 #5（時間表細化）
- 確保團隊知道「下一步做什麼」

### 💰 如果是對外融資/投資提案

- **必須** 完成 #1（市場數據）和 #4（財務模型）
- **強烈建議** 完成 #2（差異化論證）
- 其他迭代視情況補充
