# Camera 拖曳問題修復計畫

## 問題診斷

### 根本原因
1. **Canvas容器尺寸固定**：`canvas-container` 固定為 2560×1664px，超出大部分螢幕
2. **Viewport 等於地圖大小**：40×26 tiles 的地圖，viewport 也是 40×26，無拖曳空間
3. **CSS 溢出處理缺失**：沒有 `overflow: auto` 或響應式縮放

### 用戶體驗問題
- 打開編輯器只能看到地圖左上角一小部分
- 無法拖曳查看其他區域
- 無法透過滾輪縮放

## 迭代 1：完整實作（響應式 Canvas）

### 方案 A：響應式縮放（推薦）
```css
.canvas-container {
  position: relative;
  width: 100%;
  max-width: 2560px;
  height: auto;
  aspect-ratio: 2560 / 1664;
}

#game-canvas, #ui-canvas {
  width: 100% !important;
  height: 100% !important;
}
```

### 方案 B：添加滾動條
```css
.canvas-area {
  overflow: auto;
}

.canvas-container {
  width: 2560px;
  height: 1664px;
  margin: 0 auto;
}
```

### 選擇：方案 A（響應式）

## 迭代 2-10：深度審視

### 迭代 2：座標轉換審視
**問題**：響應式縮放後，滑鼠座標轉換需要考慮實際顯示比例
**解決**：使用 `getBoundingClientRect()` 獲取實際顯示尺寸

### 迭代 3：初始視角審視
**問題**：初始 camera (0,0) 可能不是最佳起始位置
**建議**：初始居中顯示地城之心

### 迭代 4：縮放邊界審視
**問題**：縮放到 0.5x 時，地圖更小，拖曳範圍更大
**驗證**：邊界限制公式需要正確計算

### 迭代 5：性能審視
**問題**：響應式 canvas 可能影響渲染性能
**優化**：使用 `requestAnimationFrame` 限制重繪頻率

### 迭代 6：小地圖整合審視
**問題**：小地圖視野框需要反映實際 viewport 大小
**修復**：根據實際 canvas 顯示尺寸計算視野框

### 迭代 7：拖曳體驗審視
**問題**：拖曳靈敏度可能過高或過低
**調整**：根據實際顯示比例調整拖曳速度

### 迭代 8：縮放中心審視
**問題**：滾輪縮放時，縮放中心可能不跟隨滑鼠
**實作**：計算滑鼠相對位置，調整 camera offset

### 迭代 9：邊界行為審視
**問題**：拖曳到邊界時可能有彈性回彈
**決策**：使用硬邊界（不允許超出）或軟邊界（允許但回彈）

### 迭代 10：全局一致性審視
**檢查**：所有 canvas 相關代碼是否考慮響應式縮放
**驗證**：編輯工具（畫筆、填充）在縮放後仍正確

## 實作計畫

### Step 1：修復 CSS（響應式）
- 移除固定 width/height
- 使用 max-width 和 aspect-ratio
- 確保 canvas 100% 填滿容器

### Step 2：修復滑鼠座標轉換
- 考慮實際顯示比例
- 使用 getBoundingClientRect()

### Step 3：測試拖曳和縮放
- 測試不同螢幕尺寸
- 驗證座標精確度
- 確認小地圖同步

### Step 4：優化體驗
- 調整拖曳靈敏度
- 實作縮放中心跟隨滑鼠
- 添加平滑過渡動畫（可選）
