# 設計文件：可滾動大地圖 + 礦車 + 英雄自主巡邏 AI

## 概述

將 ProjectDK 從固定畫面（20×13 格）擴展為可拖曳滾動的大地圖（40×26 格），加入礦車軌道互動物件，並將英雄從固定站樁改為自主巡邏 AI。

## 日期：2026-02-07

---

## 一、可滾動大地圖

### 核心架構：Camera 系統

地圖擴展為 40×26 格（640×416 像素），遊戲視窗仍顯示 20×13 格。攝影機定義可見區域。

```
世界座標 (world space): 640×416，所有遊戲物件的真實位置
畫面座標 (screen space): 320×208，實際繪製到 canvas 的位置
轉換公式: screenX = worldX - camera.x
           screenY = worldY - camera.y
```

### Config 變更

- 新增 `WORLD_COLS=40`, `WORLD_ROWS=26`
- 保留 `GRID_COLS=20`, `GRID_ROWS=13` 作為視窗大小
- Camera 邊界：`0 ≤ camera.x ≤ (WORLD_COLS - GRID_COLS) * TILE_SIZE`

### 拖曳交互

- 在 960×624 顯示 canvas 上操作
- 位移超過 5px 門檻進入拖曳模式（不觸發點擊）
- 拖曳量除以 SCALE(3x) 對應攝影機移動
- 所有點擊座標：`worldX = screenX / SCALE + camera.x`
- 遊戲不暫停（即時滾動）

### UI 層不受攝影機影響

底部陷阱面板、英雄面板、資源面板是 HUD，固定在螢幕上。

### 渲染變更

所有遊戲物件渲染函式加入 camera offset：
- map.js: 只渲染可見範圍內的格子
- enemies.js, heroes.js, traps.js: 渲染時減去 camera.x/y
- main.js effects: 同上

## 二、礦車軌道系統

### 軌道地磚

新增 `RAIL` 地磚類型，鋪在地板上，敵人可通行（不擋路），BFS 不受影響。

### 礦車資料結構

```javascript
track: {
  path: [{x, y}, ...],  // 格子座標序列
  speed: 2,              // 每秒移動幾格
  damage: 30,            // 碰撞傷害
}
```

### 行為

- 沿 path 循環行駛
- 碰撞判定：與同格的敵人/英雄碰撞
- 碰撞效果：傷害 + 擊退 1-2 格
- 占 1 格（16×16 像素精靈）

### 渲染

- 軌道：地板之上、陷阱之下
- 礦車：與敵人同層

## 三、英雄自主巡邏 AI

### 三狀態機

```
IDLE（閒晃）→ PATROL（巡邏）→ CHASE（追擊）→ IDLE
```

- **IDLE**: 部署點附近 1-2 格隨機移動，短暫停頓
- **PATROL**: 以部署點為中心，半徑 5-6 格內隨機選巡邏目標，走到停頓 1-2 秒
- **CHASE**: 偵測到敵人（攻擊射程 + 2 格），BFS 尋路追擊，到射程內停下攻擊

### 移動

- 使用格子移動系統（BFS 尋路）
- 移動速度：敵人的 60-70%
- 只能走地板格

### 回收與重新部署

- 點擊英雄 → 回收按鈕
- 回收後回到面板待部署
- 免費移陣

### 攻擊行為

完全保留現有邏輯（投射物、元素反應、進化），觸發位置從固定站樁改為射程內。
