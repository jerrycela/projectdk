## 🎨 設計審查 #1：傳送門與地城之心視覺增強

**設計師**: visual-designer
**文件路徑**: `/docs/visual-enhancements-portal-heart-design.md`
**評分**: ⭐⭐⭐⭐⭐ (5/5)

### ✅ 優點

#### 1. 視覺升級顯著
- **傳送門尺寸升級** 1×1 → 2×2,視覺衝擊力提升 4 倍 ✅
- **入口/出口色彩區分**：綠色漩渦（入口）vs 紅色漩渦（出口），符合直覺 ✅
- **動畫層次豐富**：同心圓波動（300ms）+ 漩渦旋轉（500ms）+ 核心脈動（400ms）+ 粒子飛散（800ms）✅

#### 2. 技術設計完善
- **統一渲染函數**：`DK.Map.drawHeartTile(ctx, x, y, quadrant, options)` 消除雙函數冗餘 ✅
- **參數化設計**：支援 `time`、`hpPercent`、`isFlashing` 動態選項 ✅
- **編輯器兼容**：提供 `drawPortalTile_Static()` 靜態預覽函數 ✅

#### 3. 像素藝術精細
- **地城之心水晶形態**：鑽石形狀分割，HP 依存色彩變化（紫色 → 紅色）✅
- **脈動光暈優化**：淡化至 0.08 alpha，避免過度干擾視覺 ✅
- **受傷視覺反饋**：閃紅 + 快速脈動（HP < 30% 時加速）✅

### ⚠️ 改進建議

#### 1. 色彩定義與現有色板整合 (優先級: 高)
**問題**:
```javascript

PORTAL_ENTRANCE_CORE: '#44ff44',
PORTAL_ENTRANCE_MID: '#2a9a2a',
PORTAL_ENTRANCE_DARK: '#1a5a1a',
PORTAL_ENTRANCE_GLOW: '#88ffaa',
```

**建議**:
- 這些顏色需要添加到 `config.js` 的 `DK.COLORS` 對象中
- 綠色系與現有 `HERO_SELECTED: '#44ff44'` 重複,建議統一命名：
  ```javascript
  // 建議修改為
  PORTAL_ENTRANCE_CORE: DK.COLORS.HERO_SELECTED, // '#44ff44' 重用
  ```

#### 2. 傳送門 2×2 佈局與地圖編輯器整合 (優先級: 高)
**問題**:
- 當前地圖使用單字元 `E` 標記傳送門
- 2×2 佈局需要 4 個格子,如何在 `layout` 字串中表示？

**建議方案 A（推薦）**:
```javascript
// 地圖 layout 中僅 E 標記左上角,其餘 3 格自動推斷
// Portal System 在渲染時檢測 E 並自動渲染 2×2

  'OOBWWWE......WWWBOO', // 僅標記左上角
  //      ^ 傳送門 E，實際佔據 E + 右1格 + 下1格 + 右下1格
]
```

**建議方案 B（保守）**:
```javascript
// 使用特殊符號標記 4 個象限
E = 左上, F = 右上, G = 左下, H = 右下
// 問題：佔用多個字元,與 Heart 'H' 衝突
```

**推薦**: 採用方案 A,編輯器放置 E 時自動檢查右側和下方空間。

#### 3. 性能考量：多個動畫層的開銷 (優先級: 中)
**建議**:
- 測試 10+ 傳送門同時渲染時的 FPS 影響
- 如效能不佳,考慮：
  1. 降低粒子數量（8 → 4）
  2. 增加動畫幀延遲（300ms → 400ms）
  3. 視距剔除（非視野內的傳送門跳過動畫）

**問題**:

**建議**:
```javascript
DK.Minimap = {
  position: 'top-right', // 預設右上
  // 支援 4 個位置: top-right, top-left, bottom-right, bottom-left

  setPosition(pos) {
```

#### 2. 敵人顯示性能優化可進一步加強 (優先級: 中)
**當前設計**:
```javascript
// 繪製所有敵人（僅範圍內）
for (const enemy of DK.Enemies.active) {
  const pos = this.worldToMinimap(enemy.x, enemy.y);
  ctx.fillRect(pos.x, pos.y, 2, 2);
}
```

**建議優化**:
```javascript
// 方案 1：降低更新頻率
_enemyUpdateCounter: 0,
render(ctx, time) {
  // 每 3 幀更新一次敵人位置
  this._enemyUpdateCounter++;
  if (this._enemyUpdateCounter % 3 === 0) {
    this._updateEnemies();
  }

  // 繪製快取的敵人位置
  for (const pos of this._cachedEnemyPositions) {
    ctx.fillRect(pos.x, pos.y, 2, 2);
  }
}

// 方案 2：空間分割（僅顯示視野附近）
renderEnemies(ctx) {
  const cam = DK.Game.camera;
  const viewRadius = 5; // 視野半徑（格數）

  for (const enemy of DK.Enemies.active) {
    const enemyCol = Math.floor(enemy.x / DK.CONFIG.TILE_SIZE);
    const enemyRow = Math.floor(enemy.y / DK.CONFIG.TILE_SIZE);
    const camCol = Math.floor(cam.x / DK.CONFIG.TILE_SIZE);
    const camRow = Math.floor(cam.y / DK.CONFIG.TILE_SIZE);

    // 僅顯示視野附近敵人
    if (Math.abs(enemyCol - camCol) <= viewRadius &&
        Math.abs(enemyRow - camRow) <= viewRadius) {
      const pos = this.worldToMinimap(enemy.x, enemy.y);
      ctx.fillRect(pos.x, pos.y, 2, 2);
    }
  }
}
```

**推薦**: 採用方案 1（降低更新頻率）,實作簡單且效果明顯

## 🏆 優秀設計亮點總結

### 🥇 最佳視覺設計：傳送門與地城之心
- **理由**：2×2 尺寸升級視覺衝擊力強,4 層動畫豐富但不過度,統一渲染函數消除冗餘
- **學習點**：動畫層次設計（同心圓 → 漩渦 → 核心 → 粒子）

### 🥇 最佳 UX 設計：工具欄分類重構
- **理由**：6 大分類符合工作流程,快捷鍵系統助記性強,Canvas 預覽所見即所得
- **學習點**：符合心智模型的分類邏輯

### 🥇 最佳技術設計：小地圖導航系統
- **理由**：離屏 Canvas 快取 + 按需更新,座標轉換系統清晰,效能優化到位
- **學習點**：快取失效觸發機制

### 🥇 最佳系統設計：房間系統
- **理由**：完整復刻 Dungeon Keeper 框選建造,數據結構清晰,驗證邏輯嚴謹
- **學習點**：不可變更新模式（`map(row => row.split(''))`）
