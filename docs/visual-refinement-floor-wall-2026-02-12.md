## 🎯 修改歷程

### Phase 1：DW3 風格探索（失敗）

**目標**：參考 Dungeon Warfare 3 截圖，實作類似的視覺風格

**嘗試內容**：
1. **地板設計 V1**：對角線菱形網格
   - 實作了對角線交叉的菱形圖案
   - 4 個三角形區域的明暗變化
   - 結論：與 DW3 實際風格不符 ❌

2. **地板設計 V2**：粗糙石地 + 熔岩紅點
   - 深灰綠色基調（`#2a2e2a`）
   - 色調變化區域（2-4 個）
   - 隨機噪點（8-12 個）
   - 不規則裂紋（1-3 條）
   - **熔岩紅點**（2-5 個，色調 `#cc4422` ~ `#882211`）
   - 結論：使用者滿意 ✅

3. **牆壁設計 V1**：大型不規則石塊
   - 實作了垂直/水平分割的大型石塊
   - 左上高光 + 右下陰影
   - 深色裂紋分隔
   - 結論：與原始設計落差太大 ❌

4. **牆壁設計 V2**：動態紅色邊框
   - 嘗試在牆壁與地格交界處添加紅色邊框
   - 實作了鄰接檢測邏輯
   - 結論：視覺效果不佳，使用者放棄 ❌

### Phase 2：還原原始設計（成功）

**決策**：使用者決定放棄 DW3 風格的牆壁設計，還原至美術修改前的原始磚塊設計

**執行步驟**：
1. 從 git 歷史（commit `ca0c65c`）提取原始 `drawWallTile` 函式
2. 替換 `js/map/map-tiles-basic.js` 中的牆壁繪製邏輯
3. 保留當前的地板設計（粗糙石地 + 熔岩紅點）
4. 語法檢查 + 視覺驗證

**結果**：✅ 完美還原，使用者滿意

## 🎨 最終視覺設計細節

### 地板設計（Floor Tiles）

**檔案位置**：`js/map/map-tiles-basic.js` Line 408-493

**視覺特徵**：
- **基礎色調**：深灰綠色 `#2a2e2a`
- **色調變化**：2-4 個隨機區域（`#323632` ~ `#262a26`）
- **紋理噪點**：8-12 個（`#363a36` ~ `#1e221e`）
- **不規則裂紋**：1-3 條深色裂紋（`#1a1e1a`）
- **熔岩紅點**：2-5 個（`#cc4422` ~ `#882211`）
- **變體差異**：variant 2/5/7 有額外的風化效果

**程式碼片段**：
```javascript
// 6. 添加熔岩紅點（隨機分布 2-5 個）
const lavaCount = 2 + Math.floor(rng() * 4);
for (let i = 0; i < lavaCount; i++) {
  const lx = x + 1 + Math.floor(rng() * 14);
  const ly = y + 1 + Math.floor(rng() * 14);

  const lavaRoll = rng();
  const lavaColor = lavaRoll > 0.7 ? '#cc4422'   // 亮紅
                  : lavaRoll > 0.4 ? '#aa3311'   // 中紅
                  : '#882211';                   // 暗紅

  PA.pixel(ctx, lx, ly, lavaColor);
}
```

### 牆壁設計（Wall Tiles）

**檔案位置**：`js/map/map-tiles-basic.js` Line 337-406

**視覺特徵**：
- **基礎結構**：3 排交錯磚塊（高度 5px, 4px, 5px）
- **灰縫線**：橫向深色分隔（y+5, y+10）
- **磚塊排列**：依 variant 奇偶數決定偏移（0px 或 8px）
- **色調變化**：`WALL_LIGHT`, `WALL_MID`, `WALL_WARM`, `WALL_DARK_MID`
- **立體感**：左上高光 + 右下陰影
- **紋理噪點**：每塊磚 5 個隨機噪點
- **特殊效果**：variant 2 有苔蘚（綠色斑點），variant 3 有裂紋

**程式碼片段**：
```javascript
// 磚塊排列：3 排交錯磚塊
const brickRows = [
  { y: 0, h: 5, offsets: variant % 2 === 0 ? [0, 6, 12] : [0, 8] },
  { y: 6, h: 4, offsets: variant % 2 === 0 ? [0, 8] : [0, 5, 11] },
  { y: 11, h: 5, offsets: variant % 2 === 0 ? [0, 6, 12] : [0, 8] },
];

// 灰縫線
PA.rect(ctx, x, y + 5, 16, 1, C.WALL_MORTAR);
PA.rect(ctx, x, y + 10, 16, 1, C.WALL_MORTAR);
```

### 地磚快取系統

**檔案位置**：`js/map/map-tiles-basic.js` Line 42-150

**機制**：
- 遊戲啟動時預渲染所有變體（8 個地板 + 8 個牆壁）
- 儲存在 `this.tileCache` 中（key: `floor_${v}`, `wall_${v}`）
- 渲染時直接使用快取的 canvas，無需重新繪製

**程式碼片段**：
```javascript
// 牆壁地磚變體（8 個變體）
for (let v = 0; v < 8; v++) {
  const canvas = document.createElement('canvas');
  canvas.width = T;
  canvas.height = T;
  const ctx = canvas.getContext('2d');
  this.drawWallTile(ctx, 0, 0, v);
  this.tileCache[`wall_${v}`] = canvas;
}
```

## 🎓 經驗教訓

### 1. 參考截圖的重要性

**問題**：最初基於書面描述實作了「對角線菱形網格」地板，但與實際 DW3 截圖完全不符。

**教訓**：
- 視覺設計必須以**實際截圖**為準，不能僅憑文字描述
- 在實作前應先確認參考圖片的準確性
- 分析截圖時要注意細節（紋理、色調、圖案結構）

### 2. 迭代過程中的版本控制

**問題**：經過多次迭代後，想要還原到「美術修改前的版本」時，需要從 git 歷史中提取。

**教訓**：
- 重大美術修改前應先建立**備份分支**
- git commit message 應明確標註「美術風格變更」
- 保留關鍵版本的獨立測試頁面（如 `test-original.html`）

### 3. 測試頁面的價值

**成功經驗**：
- 獨立的測試頁面（`test-dw3-fixed.html`）能快速驗證視覺效果
- Puppeteer 自動化截圖節省大量手動測試時間
- 可以並排對比不同版本的視覺效果

### 4. 使用者反饋的重要性

**歷程**：
- V1 地板（菱形網格）→ 使用者指出「落差很大」→ 立即修正
- V1 牆壁（大型石塊）→ 使用者多次反饋後決定放棄 → 還原原始設計
- V2 地板（粗糙石地 + 熔岩紅點）→ 使用者滿意「地格我覺得可以了！」→ 保留

**教訓**：
- 及早展示視覺效果，獲取使用者反饋
- 不要過度堅持技術方案，使用者體驗優先
- 如果多次迭代仍不滿意，考慮回到原點（還原原始設計）
