## 為什麼必須使用 Agent Teams？

### 1. 速度提升（3-5 倍）

**範例**：修復 3 個 Critical bugs

| 方式 | 時間 | 說明 |
|------|------|------|
| ❌ 序列執行 | 60 分鐘 | 一個一個修復（20 分鐘 × 3） |
| ✅ 並行執行 | 20 分鐘 | 3 個 agent 同時修復 |

**效率提升**：60 → 20 分鐘（**3 倍**）

### 2. 品質保證

**Opus 4.6 監督的價值**：
- ✅ 最終審查確保品質
- ✅ 協調各 agent 避免衝突
- ✅ 整合成果確保一致性
- ✅ 深度推理發現潛在問題

### 3. 專業分工

每個 agent 專注單一任務：
- Agent 1：修復 main.js
- Agent 2：修復 game.js
- Agent 3：建立測試
- Opus 4.6 Lead：整合與審查

### 4. 避免疲勞與錯誤

單一 agent 處理大量任務 → 疲勞 → 錯誤
多個 agent 分工 → 專注 → 高品質

## 適用場景（95% 的任務）

### ✅ 必須使用 Agent Teams

1. **程式碼修復**
   - 2 個以上檔案需要修改
   - 並行修復多個 bugs

2. **功能開發**
   - 任何新功能開發
   - 拆分為獨立模組並行開發

3. **測試驗證**
   - 測試多個功能
   - 並行執行不同測試

4. **文件撰寫**
   - 超過 500 字的文件
   - 並行撰寫不同章節

5. **程式碼審查**
   - 審查整個模組或系統
   - 並行審查不同維度

6. **除錯診斷**
   - 需要檢查多個可能原因
   - 並行診斷不同假設

### ❌ 唯一例外（不使用）

- 單一檔案的小修改（<10 行）
- 簡單的問答
- 快速的語法檢查

**除此之外，全部使用 Agent Teams！**

## 工作流程範例

### 範例 1：修復 3 個 Critical Bugs

```javascript
// ❌ 錯誤做法：自己一個一個修復
Read('js/main.js')
Edit('js/main.js', ...)  // Bug 1
Read('js/game.js')
Edit('js/game.js', ...)  // Bug 2
Read('js/ui.js')
Edit('js/ui.js', ...)    // Bug 3
// 總時間：60 分鐘

// ✅ 正確做法：啟動 Agent Teams
Task({
  subagent_type: "general-purpose",
  model: "sonnet",
  name: "bugfix-1",
  description: "修復 main.js Bug",
  prompt: "修復 main.js 中的 DK.FONTS.normal 錯誤"
})

Task({
  subagent_type: "general-purpose",
  model: "sonnet",
  name: "bugfix-2",
  description: "修復 game.js Bug",
  prompt: "修復 game.js 中的 DK.ENEMIES 錯誤"
})

Task({
  subagent_type: "general-purpose",
  model: "opus",
  name: "qa-lead",
  description: "QA 驗證與整合",
  prompt: "驗證所有修復並整合成果"
})
// 總時間：20 分鐘
```

### 範例 2：開發新功能

```javascript
// ✅ 並行開發
Task({ ... })  // Agent 1: 設計數據結構
Task({ ... })  // Agent 2: 實作核心邏輯
Task({ ... })  // Agent 3: 建立 UI 介面
Task({ ... })  // Agent 4 (Opus 4.6): 整合與測試
```

### 範例 3：全面 QA 測試

```javascript
// ✅ 並行測試
Task({ ... })  // Agent 1: 功能測試
Task({ ... })  // Agent 2: 性能測試
Task({ ... })  // Agent 3: 安全測試
Task({ ... })  // Agent 4 (Opus 4.6): QA Lead 整合報告
```

## 常見錯誤與改正

### 錯誤 1：自己硬做

❌ **錯誤思維**：「這個任務我自己做比較快」

✅ **正確思維**：「啟動 3 個 agent 並行，總時間更短」

### 錯誤 2：忘記監督

❌ **錯誤做法**：啟動多個 Sonnet agent，沒有 Opus 4.6 監督

✅ **正確做法**：永遠指派 Opus 4.6 作為 Team Lead 或 QA Lead

### 錯誤 3：過度序列化

❌ **錯誤做法**：Agent 1 完成 → Agent 2 開始 → Agent 3 開始

✅ **正確做法**：Agent 1、2、3 同時啟動並行執行
